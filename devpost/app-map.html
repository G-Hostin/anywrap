What it is, in four pieces

  • The browser reads the export file, writes a short summary, runs the AI's plan on every row and plays the story. The rows never leave it.
  • A small local server (server/) holds the API key and the fixed prompts, and forwards two kinds of small JSON requests to Claude.
  • The AI is called twice: once to plan (what is this file, which calculations from a fixed menu), once to write captions from computed results.
  • The number checker (src/engine/check.ts) rejects any caption number that the calculations didn't produce.

One action, followed through the code

You click the Sleep diary sample, and a card reads “0.8 points: late coffee nights scored 3.2/5, other nights 4/5”, with a receipt on its back.

Reference route (three stops)

A reference route, not a completed tour.

  1. src/pipeline.ts, search for export async function makeStory. The whole journey in order: read, summarize, plan (one repair round if a card fails), run, write captions (one rewrite if the checker objects), assemble the story. The onStep calls feed the printing receipt on the Working screen.
  2. src/engine/run.ts, search for case "compare":. This is where “0.8 points” comes from. The card's average sleep quality is computed for each value of the coffee column, the gap is formatted by fmtGap, and the receipt gets the table of groups and the note “A difference, not a cause.”
  3. src/engine/check.ts, search for export function checkCopy. Every number token in the caption must appear in that card's facts (or be the period label). Numbers written in words and “twice”, “double”, “half” are rejected. templateCaption is the fallback.

To change this, start here

You want to…Start in
Add a calculation to the menusrc/engine/types.ts (Op), src/engine/run.ts (runSlide switch), server/prompts.ts (planner text and the op enum in PLAN_SCHEMA), src/engine/check.ts (templateCaption), then a test in tests/engine.test.ts.
Change what the AI is toldserver/prompts.ts. Keep the schema flat: the API rejected optional fields and unions as “compiled grammar too large”; src/engine/plan.ts cleans the flat answer.
Change colorssrc/ui/palettes.ts (five named duotone palettes the AI picks from).
Change a chartsrc/ui/charts.tsx (bars, ranked list, month calendar, ring).
Change the receiptsrc/ui/Receipt.tsx. Its content comes from receipt in runSlide.
Read a new file formatsrc/engine/read.ts (readText) and src/engine/parse.ts (numbers, dates).
Use another modelANTHROPIC_MODEL= in .env.
Add a sample filescripts/make-samples.ts, then src/samples.ts and the expectations in scripts/check-live.ts.

A practice to reuse

Let the AI choose, let code compute, then check the AI's words against the computed results.

Where this shows up in the project

The feasibility spike (13 Oct, outside this repository) found that the AI recognized 5 unfamiliar export formats from a summary alone. The risky part was never the AI's guess; it was trusting numbers in its prose.

On the first live run of the full pipeline, the checker caught the writer typing “Four of your books” and a year that wasn't in that card's results. Both were rewritten automatically.

Evidence: tests/check.test.ts (the cases), npm run check:live (prints “caught on first pass” lines), and every receipt's last line.

How to apply it elsewhere

Any time an AI summarizes data (invoices, logs, survey results): give it a menu of calculations instead of the raw data, run them in code, and let it phrase only what the code returned. Keep a checker between the prose and the user.
